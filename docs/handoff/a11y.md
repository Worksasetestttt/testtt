# Oubli app — accessibility & interaction QA report

Method: Playwright 1.56 + axe-core 4.10.3 (wcag2a/2aa/21aa/22aa/best-practice) at 1280×800 and 390×844 on every screen of the reference flow (login → signup famille → profile → mandate → plans/checkout → dashboard → dossier → billing → settings → logout), plus keyboard tours, `input.labels`/aria-snapshot checks, viewport-overflow probes and copy regexes. Evidence files: `/tmp/claude-0/-home-user-testtt/a0b7454d-5a1f-5c23-9d25-1a916ee1124b/scratchpad/review-a11y/{report.json,report2.json,shot-*.png,run*.js}`. Source refs are to `/home/user/testtt/app/{index.html,app.js,app.css}` (current line numbers). Nothing under `/home/user/testtt` was modified.

Note: axe 4.10 ships with `duplicate-id*` rules disabled and its `label` rule matches `label[for]` textually, so it is **clean** on dossier/dashboard/billing/settings while the browser's real accessibility tree is not (findings 1–2). Do not treat "0 axe violations" as a pass.

## 1. CRITICAL — Dashboard re-renders the whole `<main>` every 6 s: keyboard focus is thrown away and the entire page is re-announced (screen: dashboard)
**Evidence.** Focus a filter button, wait 7 s → `document.activeElement === body` (report.json `6-dashboard.extra.afterPollFocus`). `loadDash()` (app.js 206-209) does `view.innerHTML = views.dashboard()` on every poll, and `<main id="view" … aria-live="polite">` (index.html 37) makes the whole view a live region. Every poll inserts a fresh subtree whose header text (`mis à jour à HH:MM`) changes, so screen readers read the full dashboard (ledger, 50 rows, journal) again every 6 seconds; a keyboard user tabbing through rows is reset to the top of the tab order every 6 s.
**Fix.**
- index.html 37: remove `aria-live="polite"` from `<main>`. Add a dedicated announcer: `<p id="announce" class="vh" role="status" aria-live="polite"></p>` and use it for route changes (`announce(document.querySelector('h1').textContent)`).
- app.js `loadDash()`: patch in place instead of replacing the view, and never touch the DOM while focus is inside it:
```js
api('/dashboard' + pid).then(function (d) {
  state.dash = d; state.user = d.user; state.profiles = d.profiles;
  if (params().route !== 'dashboard' || $('.mail')) return;
  var ae = document.activeElement, keep = view.contains(ae) && ae !== view;
  if (keep && !ae.hasAttribute('data-filter')) return;           // user is working in the page: skip this tick
  var y = window.scrollY; view.innerHTML = views.dashboard(); window.scrollTo(0, y);
  if (keep) { var b = $('.filters [data-filter="' + ae.getAttribute('data-filter') + '"]'); if (b) b.focus({ preventScroll: true }); }
});
```
(Better still: only update `#rows`, the four `.ledger__n` and `.timeline` nodes, and drop the "mis à jour à" clock from the header.)

## 2. CRITICAL — Duplicate ids on the dossier page leave the profile form's inputs unlabelled (screen: dossier, famille plan)
**Evidence.** With one profile: `f-first_name ×2`, `f-last_name ×2` (add-member form at app.js 163 and `profileForm()` both call `field()` → `id="f-<name>"`). With two profiles: 13 duplicate ids (`f-birth_date`, `f-country`, `lbl-emails`, `add-emails`, `form-msg`, …). Browser association (`input.labels`): add-member Prénom → accessible name **"Prénom Prénom Prénom"**; the "Vous" form's Prénom/Nom → `labels: []`, aria snapshot `textbox: Camille` (no name); second profile's birth date/country → no name. Playwright strict mode even fails on `#f-country`. WCAG 1.3.1 / 3.3.2 / 4.1.1 failures on the main data-entry screen.
**Fix.** Scope every generated id by profile (app.js 33-39, 92-101, 163):
```js
function field(name, label, value, attrs, hint, scope) { attrs = attrs || {}; var id = 'f-' + (scope ? scope + '-' : '') + name, hid = id + '-hint';
  return '<div class="f' + (attrs.full ? ' f--full' : '') + '"><label for="' + id + '">' + label + '</label><input id="' + id + '" name="' + name + '" value="' + esc(value) + '" ' + (attrs.extra || '') + (hint ? ' aria-describedby="' + hid + '"' : '') + '>' + (hint ? '<span class="hint" id="' + hid + '">' + hint + '</span>' : '') + '</div>'; }
function tagField(name, label, values, placeholder, hint, scope) { var base = (scope ? scope + '-' : '') + name; /* use 'lbl-'+base, 'add-'+base */ … }
```
In `profileForm(p, onboarding)` pass `scope = String(p.id).slice(0, 8)` to every `field()`/`tagField()` call and to the `<select id="f-country">` (make it `'f-' + scope + '-country'`); in the add-member form pass `'new'`. Drop `id="form-msg"` on the per-form `.msg` (app.js 100, 110, 177) — `showMsg()` already queries `.msg` within the form — and make the add-member message `<p class="msg">` too (change `showMsg(f, …, '#form-msg-add')` to `showMsg(f, …)`). Keep the onboarding ids stable (`scope` undefined) so the reference flow selectors still work.

## 3. SERIOUS — Form errors are neither announced nor attached to their field; disabling the focused submit button drops focus to `<body>` (screens: login, signup, mandate, profile, settings)
**Evidence.** Login with wrong password: during the request `button.disabled=true` and `activeElement=body`; after the error `#form-msg` = "E-mail ou mot de passe incorrect." with `role=null`, `aria-live=null`, no `[aria-invalid]` anywhere, focus still on `body`. Same for signup ("Le mot de passe doit faire au moins 10 caractères."), mandate ("Cochez la case…", checkbox has no `aria-describedby`), profile ("Prénom et nom sont obligatoires."), settings ("Mot de passe actuel incorrect."). Hints ("Au moins 10 caractères.", "Distingue vos fiches…") are not linked (`aria-describedby=null`). `busy()` (app.js 227) sets `disabled` on the focused button → Chromium blurs it.
**Fix.**
- Render every message element as `<p class="msg" role="alert" aria-atomic="true">` (app.js 64, 74, 100, 110, 163, 177, 179) — it exists at render time, so later `textContent` changes are announced.
- Replace `busy()` so the button stays focusable:
```js
function busy(form, on) { form._busy = on; var b = form.querySelector('button[type="submit"]'); if (b) { b.setAttribute('aria-disabled', on ? 'true' : 'false'); b.setAttribute('aria-busy', on ? 'true' : 'false'); } }
// top of the submit handler (app.js 247): var f = e.target; e.preventDefault(); if (f._busy) return;
```
CSS (app.css 61): `.btn:disabled, .btn[aria-disabled="true"] { opacity: .5; cursor: wait; }` and apply the same to `t.disabled = true` for `[data-checkout]`, `#launch`, `[data-resolve]` (app.js 284, 292, 293).
- Flag the field: `showMsg(form, text, isErr, sel, field)` → `if (field) { field.setAttribute('aria-invalid', 'true'); field.setAttribute('aria-describedby', ((field.getAttribute('aria-describedby') || '') + ' ' + m.id).trim()); field.focus(); }` and clear `aria-invalid` on the next submit. Pass `f.querySelector('#f-password')` for auth errors, `[name=accepted]` for the mandate checkbox, `#f-current` for the password form. Give each `.msg` a unique id for this (`'msg-' + form.id`).
- `field()`: link hints via `aria-describedby` (see snippet in finding 2).

## 4. SERIOUS — Every render drops focus to `<body>` and scrolls to the top: route changes, successful submits, the Mensuel/Annuel toggle, checkout, the profile selector (screens: all)
**Evidence.** After signup, profile save, mandate signature, checkout and `#profile-select` change: `activeElement=body`. On billing, scrolled to 408 px, activating "Mensuel" → `scrollY=0`, focus lost (`8-billing.extra.segClickScroll`), because `data-billing` calls `render()` (app.js 282) which does `view.innerHTML=…; window.scrollTo(0,0)` (187-200). Route changes via nav links keep focus on the link but never move it to the new content (no `view.focus()`).
**Fix.**
- `render()` (app.js 197-199): after `view.innerHTML = …; after(route, p.q); window.scrollTo(0, 0);` add `view.focus({ preventScroll: true });` (`tabindex="-1"` is already there) and `announce(…)` (finding 1).
- `data-billing` (282): re-render only the plans block and restore focus/scroll:
```js
else if (t.hasAttribute('data-billing')) { state.billing = t.getAttribute('data-billing'); var host = t.closest('.plans-block'); var y = window.scrollY; host.innerHTML = plansBlock(); window.scrollTo(0, y); $('[data-billing="' + state.billing + '"]', host).focus(); }
```
and wrap `plansBlock()` output in `<div class="plans-block">…</div>` (app.js 124; callers at 87 and 172 then just insert it).
- `profile-select` (309): after `loadDash()` resolves, `$('#profile-select').focus({ preventScroll: true })` (or patch in place per finding 1).
- `scrollIntoView({ behavior: 'smooth' })` (281, 307): use `behavior: matchMedia('(prefers-reduced-motion: reduce)').matches ? 'auto' : 'smooth'`.

## 5. SERIOUS — Onboarding step numerals render at 13.6 px instead of 44 px, and fail contrast (screens: onboarding 1-3; axe `color-contrast`, serious)
**Evidence.** `.rail__step span { display:block; font-size:.85rem }` (app.css 152, specificity 0,1,1) overrides `.rail__n { font-size:2.75rem }` (150, 0,1,0) and the 1023px override (278). Computed: `.rail__n` = `13.6px`, `display:block` (report2.json `rail`); `shot-rail-1280.png` vs `shot-rail-fixed-1280.png` shows the intended display numerals are missing. At 13.6px, `#C9BBA3` on `#F6F1E8` = **1.67:1** for steps 02/03 (axe nodes `li:nth-child(2) > .rail__n`, `…(3)`), and `#2E7D4F` (done) = 4.48:1 flagged because the text is small.
**Fix.** app.css 150 and 278: raise specificity so the numeral wins — `.rail__step .rail__n { … font-size: 2.75rem; display: inline-block; margin-top: 0; line-height: 1; }` and in the media query `.rail__step .rail__n { font-size: 1.75rem; }` (or change 152 to `.rail__step > div > span`). Then fix the colour of pending steps: `--border-strong` is decorative-only; use `color: var(--muted)` (5.09:1) for `.rail__n` at 150 (large text then passes 3:1 with room to spare). Verified in-browser: the selector change yields `44px`.

## 6. SERIOUS — Scrollable text regions cannot be reached with the keyboard (screens: mandate step, dossier, dashboard "Courrier"; axe `scrollable-region-focusable`, serious, 1280 & 390)

## 7. SERIOUS — A long tag breaks reflow at 390 px: horizontal page scroll (screen: profile/dossier; WCAG 1.4.10)
**Evidence.** Adding a realistic postal address ("12 rue de la Très-Longue-Dénomination-Administrative, Bâtiment C, Escalier 4, 75011 Paris") → `document.scrollWidth = 690` at a 390 px viewport; `.f` computes `grid-template-columns: 652.5px` (`report2.json.longTag390`, `shot-longtag-390-before.png`). Cause: `.f { display:grid }` (app.css 86) has an implicit `auto` column, so the `white-space:nowrap` tag span's max-content width grows the column; `.tag { max-width:100% }` then resolves against that oversized track. `.tag span` has no `title`, so once truncated the sighted user cannot read the full address either.
**Fix.** app.css 86: `.f { display: grid; grid-template-columns: minmax(0, 1fr); gap: 6px; min-width: 0; position: relative; }` (verified: scrollWidth back to 390, tag ellipsised). app.js 36 & 232: add `title="' + esc(v) + '"` / `span.title = v` on `.tag span`, or allow wrapping: `.tag span { white-space: normal; overflow-wrap: anywhere; }`.

## 9. MODERATE — "Click twice to confirm" is invisible to assistive tech and has no way back (screens: dossier "Révoquer le mandat" / "Retirer du dossier", billing "Résilier l'abonnement", settings "Supprimer le compte")
**Evidence.** First activation only swaps the button text ("Confirmer la révocation", "Confirmer la résiliation", "Confirmer le retrait"; app.js 290, 291, 303): no live region, no toast; Escape, Tab-away and a 5 s wait all leave `data-confirm=1`, so the next accidental Enter executes the destructive action (`7-dossier.extra.revokeAfter*`). The delete form instead shows "Cliquez une seconde fois pour confirmer…" in `.msg.is-error` (red, not an error) with no live region, and the button label does not change (`9-settings.extra.deleteFirstSubmit`).
**Fix.** One helper for the three buttons and the form:
```js
function arm(t, label) { if (t.getAttribute('data-confirm')) { clearTimeout(t._arm); t.removeAttribute('data-confirm'); return true; }
  t.setAttribute('data-confirm', '1'); t._label = t.textContent; t.textContent = label; t.setAttribute('aria-describedby', 'announce');
  announce(label + ' : appuyez de nouveau pour confirmer, ou Échap pour annuler.');
  t._arm = setTimeout(function () { disarm(t); }, 6000); t.addEventListener('blur', function () { disarm(t); }, { once: true }); return false; }
function disarm(t) { if (!t.getAttribute('data-confirm')) return; t.removeAttribute('data-confirm'); t.textContent = t._label; announce('Annulé.'); }
```
Use `if (!arm(t, 'Confirmer la révocation')) return;` at 290/291/303 and `if (!arm(submitBtn, 'Confirmer la suppression')) return;` at 265 (message in a `role="alert"` `.msg` but without `is-error`); add `document.addEventListener('keydown', e => { if (e.key === 'Escape') $$('[data-confirm]').forEach(disarm); })`.

## 14. MINOR — Link/button mix-ups and weak native-field focus indicator
**Evidence.** `<a href="#dashboard" data-filter="action_required">Voir lesquels</a>` (app.js 146) is a link that `preventDefault`s and filters — a button. Conversely "Courrier", "Révoquer le mandat", "Résilier l'abonnement", "Retirer du dossier", "Se déconnecter" are buttons styled as underlined text links (`.btn--ghost`), so sighted users expect navigation. Text inputs/selects remove the outline (`app.css 91, 106`) and rely on a 2 px accent underline (`box-shadow 0 1px` + border) — visible but thin for a 1280 px-wide date/select field; `.btn`, checkbox, select in the dash head and tag × keep the 2 px ring (good).
**Fix.** app.js 146: `<button type="button" class="btn btn--ghost" data-filter="action_required">Voir lesquels</button>`. Reserve `.btn--ghost` underline styling for links; give action buttons the `.btn--outline.btn--sm` look (or at least no underline). app.css 91/106: keep the underline but also `outline: 2px solid var(--accent); outline-offset: 2px;` or thicken to `box-shadow: 0 2px 0 var(--accent)`.

## 15. MINOR — French typography and micro-copy
**Evidence / fix (app.js unless noted).**
- 144-145: `'…a échoué : mettez…'`, `'Abonnement résilié' + ' : les demandes…'`, `'Mandat révoqué : plus aucune…'` use U+0020 before the colon → use `NNBSP + ': '` (same for the `' · '` separators at 83, 93, 105, 119, 152, 162, 299 → `NBSP + '· '` so a line never starts with "·").
- 43: `'Nº'` is U+00BA (ordinal indicator); French uses `N°` (U+00B0) or `nᵒ` → `'N°' + NBSP`.
- Number + unit without NBSP: "50 courtiers", "30 jours", "60 à 90 jours", "10 caractères", "5 proches", "2 éléments", "Jusqu’à 5 personnes" (73, 84, 121, 152-153, 162, 176, 119) → insert `NBSP`.
- Rendered server text (`/api/mandate`, journal messages, mail bodies) uses straight apostrophes (`d'accès`, `Demande d'effacement`) and U+0020 before `:`/`;` ("Mandant :", "tableau de bord ;") — fix in the API templates.
- Readability: `.row--head span` 10.6 px, `.f label` 10.9 px, `.timeline time`/`.filters b` 11.2 px, chips 11 px. Contrast passes (muted `#6E6558` = 5.09:1 on paper, chips ≥ 4.7:1) but raise the mono labels to ≥ 12 px (`.72rem` → `.78rem`).

---

**What passed:** axe clean on login, signup, dashboard, billing, settings at both widths; `hidden` nav/user chrome honoured; Enter in a tag input adds a tag and never submits; filter buttons update `aria-pressed` and keep focus; `#profile-select` has a (visually hidden) label and a visible ring; reduced-motion kills the chip blink, ring transition and stamp animation; no horizontal scroll at 390 on the reference screens; muted text and all chip/badge/stamp colours meet 4.5:1.

**Verdict:** Not shippable as-is for keyboard and screen-reader users — findings 1 and 2 (6-second full-view re-render inside an `aria-live` main; duplicate ids leaving the dossier form unlabelled) are blocking, and 3–4 (silent errors, focus dropped on every render) compound them.
Fixes are small and local: remove `aria-live` from `<main>`, patch instead of replace in `loadDash`, scope generated ids, use `aria-disabled` + `role="alert"` messages, and the three one-line CSS fixes (rail selector, `.f` grid column, scrollable `tabindex`).
After those, re-run `run.js`/`run2.js` from the scratchpad: the expected result is 0 axe violations on every screen, focus preserved across polls and re-renders, and `input.labels.length === 1` for every field on the dossier page.
